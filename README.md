# vpn-control

Админка VPN-проекта поверх панели [Remnawave](https://github.com/remnawave/panel). Заменяет таблицу «Траты на VPN».

Что умеет:

- **Клиенты и подписки.** У клиента-плательщика может быть несколько подписок (это пользователи Remnawave), у каждой подписки могут быть аддоны из `addons.yml` сервиса subpage.
- **Сроки.** Видно, у кого и что заканчивается: дашборд, фильтры по сроку, статус и трафик из панели.
- **Платежи с автопродлением.** Платёж зачисляется на баланс клиента. Затем появляется предпросмотр: сколько месяцев и на какие подписки и аддоны он покрывает. После подтверждения новые `expireAt` уходят в панель. Остаток остаётся на балансе.
- **Тарифы.** Есть базовые тарифы и тарифы аддонов: цена, скидки за 3, 6 и 12 месяцев, лимит трафика, стратегия сброса, HWID, сквады. Подписке можно задать индивидуальную цену. Смена тарифа считает доплату за остаток срока.
- **Аддоны.** Аддон подключается кнопкой: в панели создаётся пользователь `prefix+<username>+suffix` с параметрами тарифа, и subpage сам добавляет его в подписку.
- **Рефералы.** Дерево «кто кого привёл» и учётное начисление X% от платежей приглашённых. Процент задаётся глобально, у клиента его можно переопределить. Баланс начисления не меняют.
- **Траты в любой валюте.** Рубли считаются по курсу ЦБ на дату, плюс комиссия банка и доля (например, «домен на троих — 30%»). Сумма фиксируется при записи. Возвраты хранятся отдельно, поэтому видно, сколько потрачено до возврата и сколько вернули.
- **Тарификация по трафику.** Для CDN и подобного: `max(минимум, ГБ × цена)` по трафику ноды или участников внутреннего сквада на ней. Есть прогноз на конец месяца и список тех, кто больше всего грузит.

Стек: Go 1.26, Fiber, Ent + SQLite (без CGO). UI на Mantine 9, mantine-react-table и TanStack Query. Тема, раскладка и компоненты взяты из фронтенда Remnawave (AGPL-3.0, см. `web/THIRD_PARTY.md`). Собранный UI встраивается в бинарник.

## Запуск рядом с панелью

1. Создайте API-токен в панели (**API tokens**) со scope `users:*`, `internal-squads:read`, `nodes:read`, `bandwidth-stats:read`, `infra-billing:read` (провайдеры и даты оплат из Infra Billing) или просто `*`.
2. Заполните `.env`:

   ```bash
   cp .env.example .env
   # REMNAWAVE_TOKEN, PANEL_DOMAIN, JWT_SECRET (openssl rand -hex 32), ADDONS_FILE
   ```

3. Запустите `docker compose up -d --build`.

Контейнер подключается к сети `remnawave-network` и обращается к бэкенду напрямую (`http://remnawave:3000`). Заголовки `X-Forwarded-*`, которые требует панель, сервис выставляет сам. Контейнер публикуется на `HOST_PORT`, frp пробрасывает его на порт `1${HOST_PORT}`, и оттуда Traefik отдаёт приложение по адресу `https://<PANEL_DOMAIN>/control/`.

Вход — логином и паролем администратора панели: сервис проверяет их через `POST /api/auth/login` и выдаёт свою сессию. Если в панели вход только через OAuth или passkey, задайте `ADMIN_PASSWORD` для локального входа.

Вебхуки (по желанию) мгновенно обновляют статусы. В `.env` панели укажите:

- `WEBHOOK_ENABLED=true`
- `WEBHOOK_URL=https://<PANEL_DOMAIN>/control/api/webhooks/remnawave` — панель принимает только `https://`, поэтому вебхук идёт через её Traefik, а не напрямую в контейнер. Запросы подписаны HMAC, без верного секрета сервис их отклоняет;
- тот же секрет в `WEBHOOK_SECRET_HEADER` панели и в `WEBHOOK_SECRET` здесь.

Без вебхуков данные синхронизируются раз в `SYNC_INTERVAL` (по умолчанию 10 минут) и по кнопке ⟳.

## Резервные копии

«Настройки → Резервные копии»: экспорт выбранных категорий (клиенты, тарифы, подписки, платежи, расходы, настройки, курсы и трафик, журнал) в zip-архив и импорт такого архива на любую сборку. Архив — `manifest.json` и по JSON-файлу на таблицу. ID и даты сохраняются как есть, а столбцы, которых нет в текущей схеме, при импорте пропускаются.

Импорт целиком заменяет выбранные категории. Это одна транзакция: если в итоге останутся ссылки на отсутствующие записи (например, подписки без клиентов), она откатывается. Перед импортом текущие данные этих категорий сохраняются в `data/backups/pre-import-*.zip`.

## Разработка

```bash
task init      # .env, зависимости фронта
task dev       # API на :8080 и Vite на :5173 (проксирует /api)
task test      # go test и проверка типов фронта
task build     # bin/vpn-control со встроенным UI
```

После правки `ent/schema` запустите `task ent:generate`. Миграции применяются автоматически при старте (только аддитивные).
